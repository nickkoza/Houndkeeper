# Benchmark release

**Type:** Capability spec · **Status:** Draft · **Source:** the parked big idea of the benchmark, given back: kept
in the backlog, with the infrastructure for supporting it put in place now; principles [zGo], [CaM], [x3f] · **ID:** [WFU]

## Purpose

The procedural tidy-house sim (sim-house-nights [dws]: houses from a seed, their nights, scanned toys, photographed
floors, varied lighting, built to the realism rules [CaM] and [x3f]) could be given to others to measure against. The
release itself is parked. What is built now is what makes it one command when a release is decided: knowing what every
asset is and whether it may be passed on, scenes that regenerate byte for byte from a seed, and an export that can only
ever contain what the licences allow and nothing of the house. Nothing is published by any of it.

## Acceptance criteria

1. [h1X] **Every asset has a manifest entry.** Every asset the house generator, its nights and the item library use
   (meshes, textures, floor photos, scanned objects, imported models, fonts, and any HDRI) has an entry in a
   machine-readable manifest: what it is, where it lives, its source, its licence, the attribution it needs and where
   that was found. A licence nobody recorded is written as unknown, never guessed. An asset file on disk that no entry
   covers fails the check.
2. [kWd] **Redistributable is decided per asset, from its licence.** Each entry says whether a public release may carry
   it, decided from its licence alone by one rule; an unknown licence, a non-commercial one and anything drawn from the
   real house are not redistributable.
3. [e5I] **House and night specs are versioned.** A benchmark house is a spec: its seed, the generator's arguments, the
   floor and item split, and the generator version it was frozen at. The same spec at the same generator version (and
   the same libraries) gives byte-identical scene files.
4. [PiV] **Regeneration is verified by hashes.** Generating a spec yields a hash of every scene file (the MJCF, the
   textures, the meshes and the truth files), independent of the folder it was written to; generating it twice gives
   the same hashes, and a release carries the hashes to check against.
5. [pvP] **The export carries only what may be passed on.** The export copies only assets whose entry is
   redistributable, and lists every other asset with how to fetch it.
6. [tYQ] **Scoring travels with it.** The export includes the scoring code and the metric definitions, so a result
   from the release is scored as the project scores its own.
7. [w7W] **Hold-out houses stay out of any public tuning set.** Houses held out for judging appear in no released spec
   and are never generated by the release tooling; the release names them only as withheld. Held-out floors and items
   are labelled held out wherever they appear.
8. [MXq] **Nothing of the real house, ever** ([zGo]). The export refuses any path under `data/`, `real/` or `notes/`,
   any recording, any house-twin output or tool (house-twin [POG]: real textures never go into a released benchmark),
   the sim's run outputs, and any file holding a network address; anything derived from the real house is withheld
   whatever its licence.
9. [9SZ] **A datasheet comes with it.** The export carries a generated README: what the benchmark is, what it contains
   and leaves out and why, how to regenerate and verify it, how it is scored, and the attribution every asset needs.
10. [5JR] **The tooling publishes nothing.** The export builds a tree in a local folder and stops; uploading or
    announcing a release is a separate act, taken by hand.

## Decisions

1. [nIO] **The generator version is a hash of the generator's sources** (3 Oct 2026). `g-` and the first 12 hex digits
   of a SHA-256 over every file whose bytes decide a scene (the generator, its helpers, the floor and item lists, the
   fetch scripts that pin the assets), path and contents. Chosen over a hand-bumped number: the sim's code changes most
   days, and a number nobody bumps would claim two different generators are one. Byte-identity also depends on the
   libraries (numpy, Pillow, OpenCV, SciPy, zlib), so a hash lock records their versions beside the hashes. Checked by
   hand at the released resolution (3 Oct 2026): house 72's first tidy night with its 3 mm photographed floor, generated
   twice into different folders under different hash seeds, gave the same 14 files byte for byte (about 25 s a night
   on the laptop's CPU); the test checks the same code path at a coarse floor.
2. [OtY] **Scene hashes are taken with absolute paths written as placeholders** (3 Oct 2026). The MJCF names meshes and
   textures by absolute path (the repository's, the output folder's); before hashing, those prefixes become `${REPO}`
   and `${OUT}`, so the same scene written to two folders hashes the same, and a released scene can be rewritten to
   wherever it is unpacked.
3. [Gez] **One licence table decides redistribution** (3 Oct 2026). CC0, CC-BY 4.0, MIT, BSD-3-Clause, Apache-2.0 and the
   project's own work may be passed on (the attribution ones with their credit and licence text); unknown, any
   non-commercial licence and anything derived from the real house may not. A non-commercial asset would need the
   release itself to be non-commercial; none is in use (3 Oct 2026).
4. [HQs] **Houses 70 and 95 are released, their chosen values the project's own** (withheld
   from the public list from 3 to 28 Oct 2026). House 70's carpet colour, the slate-look tile of houses 70 and 95 and the
   demo room's (95) fireside are values chosen for the sim and carried in the generator's code as the project's own
   work ([Gez]); the values are unchanged, so every baseline and result stays comparable (public-repository [uHt]).
   Lines in the exported code that may describe the real house, and any machine paths it names, are listed for review
   by the export (`REVIEW.md`), not refused.
5. [ryb] **The export copies by allowlist** (3 Oct 2026). Only two kinds of file reach the tree: an asset whose manifest
   entry is redistributable, and a file on the generator's or the scoring's source list. Every path passes the refusal
   check before it is copied, so a new kind of real-house file is refused by not being listed, not by being recognised.
6. [1P3] **One manifest entry per source asset** (3 Oct 2026). A scanned object, an ambientCG material, an imported
   model, a robot model or a font family is one entry covering its files, with a hash over them; the item library's
   scans come from one pinned commit of `kevinzakka/mujoco_scanned_objects`, the photos from ambientCG pinned per file.
   The manifest is written by `sim/house/benchmark_release.py manifest` and checked against what the code uses.

## Before a real release (open, 3 Oct 2026)

- **Decided:** the project's own code and content are MIT (`LICENSE` at the repository's root, 28 Oct 2026).
- **Decisions still open:** the generator lines `REVIEW.md` in the dry-run export lists: keep, reword or strip each;
  whether the held-out floors and items ship (labelled `split: heldout` now).
- **Licences to confirm at their source** (the manifest took them from the repository's own notes): GSO's CC-BY 4.0,
  ambientCG's CC0, the five Sketchfab models' `meta.json` records; the MIT text of the scanned-objects conversion
  (never fetched); `ambientcg/Tiles076` (unnamed anywhere: find
  where it came from, or delete it).
- **Gaps found:** `tools/fetch_items.sh` fetches the toys but not the two pet-bowl scans; scenes silently drop a
  model missing from disk, so two machines can differ without an error; toy placement settles toys in a small
  physics run the static determinism test does not cover; `export --lock` (hashes for all released houses, about 25
  minutes of CPU) not yet run.
